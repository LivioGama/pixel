Graph extraction no longer points tree-sitter at generated or minified blobs. A committed bundle — a `*.min.js`, a precompiled `public/assets/application.js`, anything a build step wrote on one line — used to be parsed as source: on a 30-file fixture whose only other content was a 3.5 MB single-line bundle, the first graph command took 52.8 s and produced a 12 MB `graph.db` holding 36 952 symbols, of which 30 were real code and 36 922 were minified function names competing with them in every lookup and ranking. The same fixture now builds in 0.04 s into a 164 KB `graph.db` with exactly the 30 real symbols. The guard is a pure function of the bytes (a file at least 64 KiB whose mean line is at least 512 bytes), not a wall-clock parser timeout: `graph.db`'s freshness signature assumes the same bytes always yield the same graph, which a time-based bound would break. It is calibrated against real trees rather than guessed — the worst hand-written file measured in a 400k-line Rails monolith averages 127 bytes per line, so a per-line cap would have rejected real source (that repo has a 16 044-byte line in a spec) while the whole-file mean separates the two populations by orders of magnitude. It applies inside `extract_file`, `parse_file` and `extract_concepts` rather than at their call sites, which also closes a gap in the incremental path the daemon runs on every save: unlike the full build, it had no binary check at all.
