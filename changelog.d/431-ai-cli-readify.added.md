**cli:** `pixel ai-cli-readify` reports honest provider readiness for Codex, Claude Code, Antigravity and Devin. It probes Ollama Cloud, Groq and Cerebras concurrently and names each one's own condition — a missing key, a 429, a 402 with a valid credential, a gateway 400, and a model name the provider no longer serves (404) — instead of collapsing them into "unreachable", or into a status it never returned; the probe sends a real first-turn request with no system message and a real `max_tokens` reservation, so a provider that answers a 16-token toy request while throttling the real one is not reported ready. Each agent is then probed in its own lane and re-loops onto the next provider that answered when one throttles it; an authentication failure says whether a credential was rejected or was never configured, because Claude Code answers identically to both and "expired" is only true of the first; and a startup prompt (workspace trust, hook review, a sign-in prompt) is reported as the blocker rather than guessed at; `--answer-prompts` types the key only where the prompt's own text documents it. `--apply` points the agents' configs at the winning provider by merging, never replacing — it rewrites the one Codex route it owns and leaves a user's other `[model_providers.*]` entries standing, where assigning a fresh table over the key had been deleting them — and leaves Devin alone — its config is verified, never rewritten, and its readiness is its own `devin auth status` rather than a model round trip, since a provider probe would say nothing about it. `--approve --workspace <dir>` clears the named folder's own startup gate: Codex's workspace trust and its hooks' trust at the hashes Codex's app-server just computed for them, written through Codex's `config/batchWrite` RPC rather than by editing `config.toml`, and Claude's onboarding and trust dialog in `~/.claude.json` at mode 0600, keyed on the workspace's canonical path because that is the key Claude Code looks up — written under the string the caller typed, a relative or symlinked `--workspace` recorded an entry nothing would ever read, and the prompt stood while the report said trusted. It is off by default and reported either way — a trust write outlives the run, and which folders get one is the user's decision, not this command's. Antigravity and Devin have no approval path in the reference, so they report that rather than a failure. ([#431](https://github.com/LivioGama/pixel/issues/431))
